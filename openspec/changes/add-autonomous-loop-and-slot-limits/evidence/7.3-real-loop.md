# 7.3 Real loop on the real machine

Run on 2026-11-15 from this branch, with the user's go-ahead for the part
that launches nothing. The loop ran with `--apply`, the real configuration, a
temporary state directory and both limits at 0, so every iteration ended at
`capacity` and no session was launched.

## Done

```text
$ AUTONOMOUS_STATE=<tmp> bun plugins/autonomous/src/run.ts --loop --apply \
    --account claude --grills 0 --parallel 0 --interval 1 &
loop.lock: {"pid":37053,"startedAt":"2026-11-14T23:15:05.729Z"}

$ … --loop --apply --account claude --grills 0 --parallel 0     # second loop
another loop holds <tmp>/loop.lock (pid 37053, started 2026-11-14T23:15:05.729Z)
exit 3

loop.log, first iteration:
  outcome: wait
  [reconcile] advance (code)   nothing to reconcile
  [capacity] wait (code)
    grill slots 0/0  limit from flag  full
    work slots  0/0  limit from flag  full

$ … --notices 0 &                                               # waiting
$ kill -TERM 37053
loop exit 0
waiter printed:  loop stopped: received SIGTERM / next: 1   (exit 0)
loop.notices:    loop stopped: received SIGTERM
loop stdout: 0 bytes, stderr: 0 bytes; loop.lock removed
```

- A second loop is refused with code 3 and names the first.
- A full loop reads no quota and calls no LLM: the iteration stops at
  `capacity`.
- SIGTERM ends the wait at once, with code 0, the stop notice and the lock
  released. The loop prints nothing of its own.
- The waiter relays the stop notice and the new count.
